# Identity UI handoff

## Implemented here

- `styrene-identity-ui`: a scoped Dioxus page with the typed public overview client.
- `IdentityExtension`: concrete registration, generation invalidation, mount/unmount,
  enable/disable, compatible host revision, and pending-observation guard.
- `styrene-identity-desktop`: standalone lifecycle forms and an application-owned
  bounded worker calling the existing backend APIs.
- `--extension-demo`: an explicitly mocked host for the one-page contract.

The host API follows UI design commit
`a2baf72ecab685f324416f040879d356d53620b3`. The Dioxus crate and CLI are pinned
to 0.8.0-alpha.1. Current Mesh code was not modified; its active checkout remains
owned by the UI agent and has concurrent mobile work.

## Host adoption contract

Import the shared UI crate at the eventual immutable candidate revision. Supply
`OverviewClient` and `OverviewRequest` from the host session context. Reallocate
scope on source/session/selection changes. Keep ordinary Mesh controls available
when the optional page is absent or disabled. Persist only the host enable preference;
never persist secret drafts or replay mutations after restart.

The page does not expose raw paths, roots, daemon calls, or CLI execution. The
standalone shell's administrative forms are a separate host composition. Before a
Mesh mutation is wired, its host must keep the operation ID/outcome independently
observable after page closure or block disable with the specified reason.

## Local evidence

Shared page/model tests and standalone service parity tests passed. Service parity
exercises create → export → restore through the same typed services as the CLI.
Native Dioxus packaging passed and a process from the generated app bundle displayed
the disposable catalog's exact canonical ID. A stale "Reading" status was observed
and corrected to report successful public loading.

Native accessibility automation returned `osascript is not allowed assistive access`.
No acceptance is claimed for automated native lifecycle controls, VoiceOver, mobile
devices, Linux desktop, or actual Mesh host integration. See the runtime evidence
ledger for source/artifact/process/capture attribution.
