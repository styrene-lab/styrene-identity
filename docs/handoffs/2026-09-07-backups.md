# Backup implementation handoff

The managed artifact service now implements ID30–ID36, legacy recovery migration,
and unified operation discovery. See [backup management](../backup-management.md).
The private artifact ledger owns staging before ciphertext writes and authenticates
the expected identity before publication. Deletion verifies the quarantined object
before unlinking; replacements are preserved.

Validation on Rust 1.97.0, `aarch64-apple-darwin`:

- `cargo test --locked -p styrene-identity-lifecycle --features file-custody mutations::artifacts --quiet -- --test-threads=2`:
  10 artifact tests passed, including all write boundaries, partial staging,
  disappeared source, restored catalog registration, forged digests, quarantine
  races, and legacy migration.
- `cargo test --locked -p styrene-identity-lifecycle -p styrene-identity-cli --quiet -- --test-threads=2`
  passed before the final additional artifact cases; the expanded corpus is
  checked again at the final release-candidate checkpoint.
- Warning-denied Clippy passed for the lifecycle/CLI packages after those changes.

The artifact-capable store guard is a forward-writer boundary. Older clients must
not ignore pending artifact operations. Migrated catalog receipts use version 3;
ordinary v1/v2 records remain readable. No ciphertext format or derivation profile
changed. Source/destination credential roles remain separate and are never stored
in ledgers.

The user-owned UI checkout remains unchanged. Standalone UI and mock-host work
continues in this repository against these typed services. Native UI, physical
devices, network filesystems, and actual Mesh host adoption are separate evidence.
